## 🏛️ Project Architecture & Tech Stack

This project is a **Real-Time Chat Application** built with the following core technologies:
- **Frontend**: [React 19](https://react.dev) + [Vite 7](https://vite.dev) (Single Page Application, JavaScript).
- **Styling**: Vanilla CSS (modular stylesheets matching component names, e.g., `ChatBox.css` next to `ChatBox.jsx`).
- **Database & Auth**: [Firebase](https://firebase.google.com) (Authentication for login/signup, Firestore for database).
- **Media Storage**: [Supabase Storage](https://supabase.com/docs/guides/storage) (handling image and media uploads).
- **Hosting**: Firebase Hosting (`chat-app-d042d.web.app`).

## 💾 Database Schema & State Management

The application manages data inside Google Cloud Firestore with three core collections:

### 1. `users` Collection
Stores metadata for registered users.
- **Document ID**: User's Firebase UID.
- **Fields**:
  ```typescript
  {
    id: string;        // Firebase UID
    username: string;  // Unique username in lowercase
    email: string;     // Email address
    name: string;      // User display name
    avatar: string;    // URL link to user profile image (stored on Supabase)
    bio: string;       // Custom profile status/biography
    lastSeen: number;  // Epoch timestamp updated periodically for presence
  }
  ```

### 2. `chats` Collection
Stores metadata about recent chat threads for each user.
- **Document ID**: User's Firebase UID.
- **Fields**:
  ```typescript
  {
    chatData: Array<{
      rId: string;          // Receiver's User UID
      lastMessage: string;  // Preview of the last message sent/received
      updatedAt: number;    // Epoch timestamp of the last message
    }>
  }
  ```

### 3. `messages` Collection
Stores the actual message logs for individual user-to-user conversations.
- **Document ID**: Combined sorted user UIDs (`conversationId`), generated by joining the alphabetical sort of the two participant UIDs, separated by an underscore (`[uid1, uid2].sort().join('_')`).
- **Fields**:
  ```typescript
  {
    messages: Array<{
      sId: string;         // Sender's User UID
      text: string;        // Message text content
      image: string;       // URL string of uploaded image (if any)
      timestamp: number;   // Epoch timestamp of message delivery
    }>
  }
  ```

## 📡 Key Core Workflows

### 1. Dynamic User Presence Tracking
- Updates the user's online state by storing their `lastSeen` timestamp in their Firestore user document.
- Triggered on login/signup and updated periodically every **60 seconds** via a `setInterval` in a `useEffect` inside [AppContext.jsx](file:///c:/Users/STAR%20Zx/Desktop/project/chat-app/chat-app/src/context/AppContext.jsx).
- The interval is properly cleared on component unmount or logout to avoid memory leaks.
- A user's online status in the UI is computed dynamically: `isOnline = selectedUser && (Date.now() - selectedUser.lastSeen < 120000)`. If offline, a CSS filter `.offline` turns the green dot grey.

### 2. Real-Time Chat List (Hydrated Sidebar)
- Listens to the user's `chats` document in real time with an `onSnapshot` listener in [AppContext.jsx](file:///c:/Users/STAR%20Zx/Desktop/project/chat-app/chat-app/src/context/AppContext.jsx).
- Whenever a chat item updates, the recipient's metadata is loaded dynamically, and the chat thread list is sorted by the most recent message (`updatedAt` descending).

### 3. Query-Based User Search
- Instead of downloading the entire database, user searches in [LeftSidebar.jsx](file:///c:/Users/STAR%20Zx/Desktop/project/chat-app/chat-app/src/components/LeftSidebar/LeftSidebar.jsx) utilize prefix-based Firestore queries (`where('username', '>=', queryTerm)`), debounced by `400ms` to scale efficiently and protect user privacy.

### 4. File and Media Sharing
- Images/media are uploaded to **Supabase Storage** under the bucket `chat-images` using the helper in [upload.js](file:///c:/Users/STAR%20Zx/Desktop/project/chat-app/chat-app/src/lib/upload.js).
- When a file is selected in [ChatBox.jsx](file:///c:/Users/STAR%20Zx/Desktop/project/chat-app/chat-app/src/components/ChatBox/ChatBox.jsx), it is uploaded to Supabase, which yields a public URL. This URL is then sent as a message (with `image` populated and `text` empty) stored in Firestore.

## 🛠️ Guidelines for AI Changes & Code Editing

1. **Environment Variables Config**: SDKs are initialized in `src/config/firebase.js` and `src/config/supabase.js` using Vite environment variables (`import.meta.env.VITE_*`). Avoid hardcoding API credentials. Keep local configs inside [chat-app/.env](file:///c:/Users/STAR%20Zx/Desktop/project/chat-app/chat-app/.env) which is ignored by `.gitignore`.
2. **Vanilla CSS Styling**: Use standard CSS files placed alongside components. Avoid using TailwindCSS or utility libraries unless explicitly requested. Ensure selectors are specific and do not bleed.
3. **Responsiveness Rules**: 
   - Mobile breaks are set at `< 768px`. Grid layouts change to single column `1fr`.
   - Toggle view is managed using the `.chat-selected` class on the container element.
   - Use `height: 100dvh` on mobile components to support dynamic mobile viewport adjustments when the virtual keyboard is toggled.
4. **React Router usage**: The routing uses standard routes `/`, `/Chat`, and `/Profile` managed inside `App.jsx`. Use `useNavigate` from `react-router-dom` for view redirection.
